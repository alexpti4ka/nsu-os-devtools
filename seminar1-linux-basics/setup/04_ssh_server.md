# Подготовка к семинару: работа на Linux-сервере по SSH

Этот вариант предназначен для студентов, которые не могут установить Linux, виртуальную машину или WSL. Вы будете выполнять задания на Linux-сервере семинариста через SSH.

## 1. Получите данные для подключения

Семинарист выдаст:

- адрес сервера: `<host>`;
- порт SSH: обычно `22`, но может быть другим;
- имя пользователя: `<login>`;
- способ аутентификации: пароль или SSH-ключ;
- **fingerprint SSH-ключа сервера**, с которым нужно сверить первое подключение.

Не публикуйте пароль и другие выданные данные в общих чатах.

## 2. Откройте терминал на своём компьютере

### Windows

Откройте Windows Terminal или PowerShell.

### macOS / Linux

Откройте обычное приложение Terminal.

На современных системах команда `ssh` обычно уже установлена.

Проверьте:

```bash
ssh -V
```

Если команда не найдена, обратитесь к семинаристу.

## 3. Подключитесь

Если используется стандартный порт 22:

```bash
ssh <login>@<host>
```

Если семинарист указал другой порт:

```bash
ssh -p <port> <login>@<host>
```

Например:

```bash
ssh -p 2222 student17@server.example.org
```

## 4. Проверьте fingerprint при первом подключении

При первом соединении SSH может показать сообщение о неизвестном host key и вывести fingerprint сервера.

**Сравните этот fingerprint с тем, который сообщил семинарист.** Только после совпадения подтвердите подключение.

Это важная часть модели безопасности SSH: не следует автоматически отвечать `yes` на неизвестный ключ сервера.

## 5. Введите пароль

Если используется пароль, SSH запросит его после подключения.

При вводе пароля символы обычно **не отображаются вообще**. Это нормально. Введите пароль и нажмите Enter.

## 6. Убедитесь, что вы действительно на Linux-сервере

После подключения выполните:

```bash
whoami
hostname
pwd
uname -a
cat /etc/os-release
```

Обратите внимание: эти команды теперь выполняются **не на вашем ноутбуке, а на удалённом сервере**.

Создайте каталог для работы:

```bash
mkdir -p ~/university/seminar1
```

## 7. Завершите соединение и подключитесь снова

Для выхода:

```bash
exit
```

После этого ещё раз подключитесь той же командой `ssh` и проверьте, что созданный каталог сохранился.

## Что важно помнить

- Ваши учебные файлы находятся на сервере, а не на локальном компьютере.
- Разрыв SSH-соединения не удаляет сохранённые файлы.
- Для работы нужен доступ к сети.
- Не изменяйте чужие каталоги и системные настройки сервера.
- Для команд, требующих `sudo`, сначала уточните правила у семинариста: учебная учётная запись может намеренно не иметь административных прав.

## Частые ошибки

### `Connection timed out` / `No route to host`

Проверьте сеть, адрес и порт. Если они верны, обратитесь к семинаристу.

### `Permission denied`

Проверьте имя пользователя и способ входа. Не перебирайте пароль многократно — покажите сообщение семинаристу.

### `REMOTE HOST IDENTIFICATION HAS CHANGED`

Не удаляйте запись из `known_hosts` автоматически. Такое сообщение может появиться после переустановки учебного сервера, но сначала подтвердите новый fingerprint у семинариста.
