Git — семинар: учебный стенд (workbench)
=========================================

Назначение
----------
Этот каталог содержит скрипт, который разворачивает набор готовых учебных
репозиториев для практической части семинара по Git. Стенд самодостаточен:
для «удалённого» хранилища используется локальный bare-репозиторий,
так что реальный GitHub не требуется. Всё выполняется в выданной на
`pglab.nsu.ru` виртуальной машине.

Быстрый старт (студент)
-----------------------
1. Убедитесь, что установлен git:  git --version
2. Разверните стенд (в любом каталоге, например в ~/gitlab):

       mkdir -p ~/gitlab && cd ~/gitlab
       bash /путь/к/git-workbench/setup.sh

3. Скрипт создаст:
   - 01-basics/     — обычный каталог с файлами, ещё НЕ репозиторий;
                      здесь выполняется git init и базовый цикл
                      (status / add / commit, «три области»).
   - 02-branching/  — репозиторий с ветками main и feature; слияние
                      feature в main порождает конфликт, который нужно
                      разрешить вручную.
   - 03-history/    — репозиторий с 7 коммитами и тремя «авторами»
                      (Алиса/Боб/Каролина). В одном из коммитов заложен
                      баг: test.sh до него проходит (OK), после него
                      падает (FAIL). Для git blame и git bisect.
   - remote.git/    — bare-репозиторий, играет роль «сервера» для
                      remote / push / clone / pull / fetch.

Особенности
-----------
- Истории коммитов создаются с фиксированными датами и авторами, поэтому
  вывод log / blame / bisect одинаков у всех студентов.
- Скрипт идемпотентен: повторный запуск пересоздаёт все каталоги заново
  (старые 01-basics, 02-branching, 03-history, remote.git удаляются).
- Для коммитов/слияний в репозиториях студенту нужна git-идентичность
  (user.name / user.email) — она задаётся в Задаче 1 семинара.

Для семинариста
---------------
- Баг в 03-history введён коммитом «compute: упростить выражение»
  (заменили 6 * 7 на 6 + 7). git bisect должен указывать именно на него.
- Конфликт в 02-branching — на «Строке 2» файла message.txt:
  main и feature по-разному её изменили.
- См. Методическое_пособие_семинар_5.md и Семинар 5. Git.md.
