# Практическая работа

Привет!

В этой работе ты повторишь знакомые команды Linux и познакомишься с процессами, нагрузкой, systemd, сетевыми портами и журналами.

Работай от своего обычного пользователя. Не переходи в `root` через `sudo su`. Используй `sudo` только там, где это указано в задании.

## Часть 0. Подготовка

### Шаг 0. Создай директорию для результатов

Команда:

```bash
mkdir -p /tmp/os-lab-results
```

Ожидаемый результат: директория `/tmp/os-lab-results` создана.

Пояснение: `mkdir` создает директорию. Ключ `-p` позволяет создать весь путь и не выдает ошибку, если директория уже существует.

Теперь включи запись терминальной сессии:

```bash
script -a /tmp/os-lab-results/session.txt
```

Ожидаемый результат: появится сообщение о начале записи сессии.

Пояснение: `script` записывает введенные команды и их вывод в файл. Ключ `-a` дописывает данные в существующий файл, если он уже есть.

С этого момента выполняй команды задания как обычно. Их вывод будет записываться автоматически.

Важно: содержимое `/tmp` может быть удалено после перезагрузки. Создай архив до завершения работы.

## Часть 1. Установка и повторение

### Шаг 1. Найди пакет

Команды:

```bash
pwd
ls -lah
```

Ожидаемый результат: в текущем каталоге виден файл `os-lab.deb`.

Пояснение:

- `pwd` показывает текущий каталог.
- `ls -lah` показывает файлы, включая скрытые, а также права, владельца и размер.
- `-l` включает подробный формат.
- `-a` показывает скрытые файлы.
- `-h` показывает размеры в удобном виде.

### Шаг 2. Установи пакет

Команда:

```bash
sudo apt install ./os-lab.deb
```

Ожидаемый результат: пакет `os-lab` установлен, необходимые зависимости установлены автоматически.

Пояснение: `apt install` устанавливает пакет и его зависимости. `sudo` выполняет одну команду с административными правами.

Проверь установку:

```bash
dpkg -s os-lab | grep Status
```

Ожидаемый результат:

```text
Status: install ok installed
```

### Шаг 3. Узнай свой ID, IP и port

Команда:

```bash
os-lab-info
```

Ожидаемый результат похож на:

```text
ID: A1B2C3D4E5
IP: 127.77.15.42
port: 23456
Адрес: http://127.77.15.42:23456/
```

Сохрани IP и port, они понадобятся дальше.

Открой адрес из строки `Адрес` в браузере (например, на вм). На странице должны появиться две картинки и сообщение `ERROR`.

Не исправляй это сообщение сейчас. Оно понадобится далее (в задании со звездочкой).

Для удобства сохрани IP и port в переменные текущей shell-сессии:

```bash
IP="ТВОЙ_IP"
PORT="ТВОЙ_PORT"
```

Пример:

```bash
IP="127.77.15.42"
PORT="23456"
```

Проверь значения:

```bash
echo $IP
echo $PORT
```

### Шаг 4. Посмотри конфигурацию

Команды:

```bash
cd /etc/os-lab
pwd
ls -lah
cat config.ini
cat identity.conf
```

Ожидаемый результат: ты находишься в `/etc/os-lab` и видишь файлы конфигурации сервиса.

Пояснение: `/etc` обычно содержит системную конфигурацию.

### Шаг 5. Найди port в конфигурации

Команда:

```bash
grep -n "port" /etc/os-lab/config.ini
```

Ожидаемый результат: строка с port сервиса.

Пояснение: `grep` ищет строки по указанному тексту. Ключ `-n` добавляет номер строки.

### Шаг 6. Повтори права доступа

Важно: выполняй этот шаг от своего обычного пользователя. Не используй `sudo su` и не выполняй весь шаг от `root`.

Скопируй учебный файл:

```bash
cp /usr/share/os-lab/practice/hello.sh ~/hello-os-lab.sh
cd ~
chmod 644 ~/hello-os-lab.sh
ls -lah ~/hello-os-lab.sh
```

Попробуй выполнить файл:

```bash
./hello-os-lab.sh
```

Ожидаемый результат: файл не выполняется как программа, потому что у него нет права выполнения.

Теперь добавь право выполнения:

```bash
chmod +x ~/hello-os-lab.sh
./hello-os-lab.sh
```

Ожидаемый результат:

```text
Скрипт успешно запущен
```

Пояснение:

- `chmod 644` задает чтение и запись владельцу и только чтение остальным.
- `chmod +x` добавляет право выполнения.

### Шаг 7. Сделай копию конфигурации

Команды:

```bash
cp -v /etc/os-lab/config.ini /tmp/os-lab-results/config-copy.ini
mv -v /tmp/os-lab-results/config-copy.ini /tmp/os-lab-results/config-backup.ini
diff -u /etc/os-lab/config.ini /tmp/os-lab-results/config-backup.ini
```

Ожидаемый результат: `diff` ничего не выводит, потому что файлы одинаковые. Но отобразиться вывод о смене имени при перемещении.

Пояснение:

- `cp` копирует файл. Первый аргумент указывает источник, второй место назначения.
- `-v` у `cp` показывает, что именно было скопировано.
- `mv` перемещает или переименовывает файл.
- `-v` у `mv` показывает выполненное перемещение.
- `diff` сравнивает файлы.
- `-u` у `diff` выводит различия в текстовом формате, если они есть.

## Часть 2. Процессы и ресурсы

### Шаг 8. Найди процесс сервиса

Команды:

```bash
ps aux | grep 'os-lab'
pgrep -af os-lab
```

Ожидаемый результат: среди процессов есть запущенный `os-lab`.

Пояснение:

- `ps` показывает процессы.
- `a` добавляет процессы других пользователей.
- `u` включает подробный пользовательский формат.
- `x` добавляет процессы без управляющего терминала.
- `|` передает вывод одной команды на вход следующей.
- `grep` оставляет строки, подходящие под условие поиска.
- `pgrep` ищет PID процесса.
- `-a` у `pgrep` показывает PID вместе с командой.
- `-f` ищет по полной командной строке.

Обрати внимание на PID и пользователя процесса.

### Шаг 9. Посмотри процессы в реальном времени

Команда:

```bash
htop
```

Если `htop` не установлен, используй:

```bash
top
```

Ожидаемый результат: список процессов с текущей нагрузкой CPU и памяти.

Выйди из `htop` или `top` (Ctrl + C), затем выполни:

```bash
top -b -n 1
```

Пояснение:

- `-b` запускает `top` в пакетном режиме.
- `-n 1` выполняет одно обновление и завершает работу.

Именно этот вывод удобнее использовать при проверке работы.

### Шаг 10. Создай CPU-нагрузку

Команда:

```bash
curl "http://$IP:$PORT/load/cpu?seconds=30"
```

Ожидаемый результат: сервис сообщает PID процесса нагрузки.

Сразу выполни:

```bash
ps aux | grep 'oslab-cpu'
top -b -n 1
```

При желании открой `htop` и найди процесс `oslab-cpu`.

Пояснение: сервис создает отдельный процесс, который примерно 30 секунд активно использует CPU.

### Шаг 11. Создай нагрузку на память

Посмотри состояние памяти:

```bash
free -h
```

Запусти нагрузку:

```bash
curl "http://$IP:$PORT/load/memory?mb=120&seconds=30"
```

Сразу после запуска снова выполни:

```bash
free -h
ps aux | grep 'oslab-memory'
```

Ожидаемый результат: на короткое время объем занятой памяти увеличивается.

Пояснение: `free` показывает использование оперативной памяти. Ключ `-h` выводит размеры в удобных единицах, например MiB и GiB.

## Часть 3. systemd, сеть и журналы

### Шаг 12. Проверь состояние сервиса

Команда:

```bash
systemctl status os-lab --no-pager
```

Ожидаемый результат: состояние `active (running)`.

Пояснение:

- `systemctl` работает с сервисами systemd.
- `--no-pager` выводит результат прямо в терминал без отдельного просмотрщика.

Обрати внимание на `Main PID`.

### Шаг 13. Найди сетевой port

Команда:

```bash
sudo ss -lntp | grep "$PORT"
```

Ожидаемый результат: строка с твоим IP, port и процессом, который слушает этот port.

Пояснение:

- `ss` показывает сетевые socket.
- `-l` показывает только слушающие socket.
- `-n` оставляет IP и port в числовом виде.
- `-t` показывает TCP.
- `-p` показывает связанный процесс, если хватает прав.

### Шаг 14. Посмотри журналы

Команда:

```bash
journalctl -u os-lab --no-pager -n 20
```

Пояснение:

- `journalctl` читает системный журнал.
- `-u os-lab` оставляет сообщения сервиса `os-lab`.
- `--no-pager` выводит текст прямо в терминал.
- `-n 20` показывает последние 20 строк.

Также посмотри файловый журнал:

```bash
tail -n 20 /var/log/os-lab/app.log
```

Пояснение: `tail -n 20` показывает последние 20 строк файла.

### Шаг 15. Создай HTTP-ошибку и найди ее

Команда:

```bash
curl -i "http://$IP:$PORT/error"
```

Ожидаемый результат: HTTP-ответ с кодом `500` и текстом `ERROR`.

Пояснение: ключ `-i` у `curl` добавляет HTTP-заголовки к выводу, поэтому можно увидеть код ответа сервера.

Найди ошибку в журнале:

```bash
journalctl -u os-lab --no-pager | grep ERROR
```

После ошибки проверь, продолжает ли сервис работать:

```bash
curl -i "http://$IP:$PORT/health"
```

Команды:

```bash
cd /tmp
tar -czf os-lab-results.tar.gz os-lab-results/
ls -lah /tmp/os-lab-results.tar.gz
```

Пояснение:

- `tar` работает с архивами.
- `-c` создает новый архив.
- `-z` использует gzip-сжатие.
- `-f` указывает, что дальше задано имя файла архива.

Проверь содержимое архива:

```bash
tar -tzf /tmp/os-lab-results.tar.gz
```

Пояснение: `-t` показывает содержимое архива без распаковки.
