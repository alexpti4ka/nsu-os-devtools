Это домашнее задание закрепляет тему семинара «Компиляция и системы сборки», раздел про этапы компиляции, заголовочные файлы и раздельную компиляцию.

## Задача 1. Один исходник, два компилятора, разные предупреждения

### Условие

Файл: `warn.c`. В нём три потенциальные проблемы, которые компилятор может заметить.

Скомпилируйте его тремя способами каждым из компиляторов (`gcc` и `clang`):

1. без флагов;
2. с `-Wall -Wextra`;
3. с `-Wall -Wextra -Werror`.

Два первых результата сохраните (текст предупреждений идёт в стандартный поток ошибок, поэтому нужен перенаправляющий `2>`):

```bash

clang -Wall -Wextra -c warn.c -o /tmp/warn.o 2> gcc-results/warn-clang.txt
```

Третий способ зафиксируйте как доказательство, что файл не собирается:

```bash
gcc -Wall -Wextra -Werror -c warn.c -o /tmp/warn.o 2> gcc-results/warn-werror.txt
```

Последняя команда завершится с ошибкой — это ожидаемо.

Запишите в `gcc-results/answers.txt`:

1. какие предупреждения выдал каждый компилятор и чем отличаются их формулировки;
2. что делают флаги `-Wall`, `-Wextra` и `-Werror`;
3. почему в реальных проектах эти флаги включают по умолчанию.

### Инструменты

`gcc`, `clang`, `2>`, `man gcc`, `man clang`

### Самопроверка

- `gcc-results/warn-gcc.txt` и `gcc-results/warn-clang.txt` непустые: найдено минимум **3** предупреждения (неиспользуемая переменная, неинициализированная переменная, несоответствие формата `%d` и типа `long`);
- `gcc-results/warn-werror.txt` содержит сообщение об ошибке (`error:`), потому что `-Werror` превращает предупреждения в ошибки;
- без флагов компилятор молчит и создаёт исполняемый файл.

## Задача 2. Весь конвейер компиляции вручную

### Условие

Препроцессор:

```bash
gcc -E pipeline.c -o gcc-results/pipeline.i
```

Компилятор в ассемблер:

```bash

```

```bash
gcc -c gcc-results/pipeline.s -o gcc-results/pipeline.o
```

Линковка:

```bash
gcc gcc-results/pipeline.o -o gcc-results/pipeline
```

Запустите готовую программу и сохраните вывод:

```bash
./gcc-results/pipeline > gcc-results/pipeline-run.txt
```

Для каждого файла из цепочки `pipeline.c → pipeline.i → pipeline.s → pipeline.o → pipeline` определите тип и размер:

```bash

stat -c '%s %n' pipeline.c gcc-results/pipeline.i gcc-results/pipeline.s gcc-results/pipeline.o gcc-results/pipeline
```

Исследуйте результат:

* найдите в `gcc-results/pipeline.i`, во что развернулся макрос `SQUARE(i)` и куда делась константа `LIMIT`;
* найдите в `gcc-results/pipeline.s` функцию `sum_squares` и определите, где в ней цикл;
* проверьте себя: выполните `gcc -save-temps pipeline.c -o /tmp/check` и сравните полученные файлы со своими (`diff` или `cmp`);
* повторите стадию `-S` с Clang (`clang -S pipeline.c -o /tmp/pipeline-clang.s`) и сравните ассемблер с gcc-версией.

Ответы на вопросы «что лежит в `.i`, `.s`, `.o`» и «почему `.i` заметно больше исходника» запишите в `gcc-results/answers.txt`.

### Инструменты

`gcc -E`, `gcc -S`, `gcc -c`, `gcc`, `clang`, `-save-temps`, `file`, `stat`, `diff`, `cmp`, `less`, `grep`, `man`

### Самопроверка

- `file` показывает: `.i` и `.s` — текст, `.o` и `pipeline` — бинарные файлы;

gcc -Iinclude -E src/main.c -o gcc-results/main.i

Дополнительный эксперимент: замените в `shape.h` `#define AREA_SQUARE(a) ((a) * (a))` на `#define BAD_SQUARE(a) a * a`, вызовите `BAD_SQUARE(p.x + 1)` и посмотрите раскрытие. Объясните в `answers.txt`, зачем нужны скобки в макросах. Затем верните `shape.h` в исходное состояние.

## Задача 6. Полная и раздельная компиляция

### Условие

Проект: `calc/` (три файла в `src/`, два заголовка в `include/`). Результаты складывайте в `gcc-results`.

**Полная сборка** — одна команда компилятору отдаёт все исходники сразу:

```

**Раздельная компиляция** — каждый `.c` сначала превращается в объектный файл, затем объектные файлы линкуются:

gcc -Icalc/include -c calc/src/mathx.c -o gcc-results/obj/mathx.o
gcc -Icalc/include -c calc/src/strx.c -o gcc-results/obj/strx.o
gcc gcc-results/obj/main.o gcc-results/obj/mathx.o gcc-results/obj/strx.o -o gcc-results/calc-separate
```

1. Запустите `gcc-results/calc-separate` и убедитесь, что вывод совпадает с полной сборкой (`5`, `20`, `3`).
2. Запишите времена объектных файлов:

```bash
stat -c '%n %y' gcc-results/obj/*.o > gcc-results/timestamps.txt
```

3. Добавьте комментарий в `calc/src/strx.c`, пересоберите **только** `strx.o` и перелинкуйте программу. Проверьте по `timestamps.txt`: изменился только `gcc-results/obj/strx.o`.
4. Теперь выполните общую команду полной сборки из начала задачи и снова проверьте времена `gcc-results/obj/*.o`. Объясните в `answers.txt`, почему они не изменились.
5. Верните `calc/src/strx.c` в исходное состояние.

### Инструменты

`gcc`, `-I`, `-c`, `stat`, `touch`, `diff`, `man`

### Самопроверка

- обе программы печатают `5`, `20`, `3` (`gcc-results/calc-run.txt`);
- в `gcc-results/obj/` лежит ровно три объектных файла;
- при правке одного `.c` пересобирается только его объектный файл — в этом и смысл раздельной сборки: экономится время;
- вы можете объяснить, чем полная сборка отличается от раздельной и почему компиляция каждого `.c` в отдельности не зависит от других файлов проекта.

## Задача 7. Ошибки линковщика

## Проверка и сдача работы

### Артефакт

Работа сдаётся одним архивом. Его готовит проверяющий скрипт, но убедитесь, что каталог `gcc-results/` содержит все файлы:

| Файл | Из какой задачи |
|---|---|
| `warn-gcc.txt`, `warn-clang.txt`, `warn-werror.txt` | задача 1 |
| `pipeline.i`, `pipeline.s`, `pipeline.o`, `pipeline`, `pipeline-run.txt` | задача 2 |
| `main.i` | задача 4 |
| `main2-noguard.i`, `main2-guard.i` | задача 5 |
| `obj/main.o`, `obj/mathx.o`, `obj/strx.o`, `calc`, `calc-run.txt`, `timestamps.txt` | задача 6 |
| `link-error-a.txt`, `link-error-b.txt` | задача 7 |
| `answers.txt` | письменные ответы на вопросы из всех задач |
| `session.txt` | запись терминальной сессии (`script`) |

Перед сдачей верните изменённые в ходе экспериментов исходники: `git status` должен показывать только незнакомые файлы `gcc-results/`, но не правки в `include/`, `src/` и `calc/`.

### Как проверить работу

Из каталога задания выполните:

```bash
chmod +x check.sh
./check.sh
```

Скрипт проверит состав `gcc-results/`, содержимое ключевых файлов и исходные файлы задания, напечатает результаты проверок и, если всё в порядке, соберёт архив `s3-compile.tar.gz`. Можно приложить скриншот этого вывода.

### Как передать работу

Отправьте файл `s3-compile.tar.gz` своему семинаристу удобным способом — канал связи уточните на занятии (например, телеграм или почта). В теме сообщения укажите: `s3-compile — ФИО`.
