# Домашнее задание. Система сборки: Makefile для проекта calc

Это домашнее задание закрепляет тему семинара «Компиляция и системы сборки», раздел про систему сборки `make`.

Писать код на C не нужно: проект `calc/` уже лежит рядом с заданием. Ваша работа — описать его сборку в `Makefile`, разобраться в структуре правил и убедиться, что `make` действительно пересобирает только нужные файлы.

Ответы на вопросы «Почему...», «Что напечатал второй запуск?», «Чем `touch` отличается от правки?» записывайте по мере работы в `make-results/answers.txt` — они входят в артефакт работы (см. раздел «Проверка и сдача работы»).

---

## Материалы

Небольшой проект `calc/`:

```text
Сборка-make/
└── calc/
    ├── include/
    │   ├── mathx.h     объявления функций add и mul
    │   └── report.h    объявление функции print_result
    ├── src/
    │   ├── main.c      печатает результаты
    │   ├── mathx.c     реализация add и mul
    │   └── report.c    реализация print_result
    └── expected.txt    ожидаемый вывод программы
```

Схема сборки, которую нужно воспроизвести в `Makefile`:

```text
src/main.c   → build/main.o   ─--┐
src/mathx.c  → build/mathx.o  ─┼─► calc
src/report.c → build/report.o --─┘
```

Итоговый исполняемый файл называется `calc` и печатает:

```text
add: 5
mul: 20
```

### Инструменты

`make`, `gcc`, `diff`, `stat`, `touch`, `cat`, `man make`, `vim`

## Задача 1. Первый явный Makefile

### Условие

Напишите `Makefile` для проекта в каталоге `hw1`. На первом этапе он должен быть намеренно **явным**: отдельное правило для каждого объектного файла.

В Makefile должны быть цели:

```text
all
calc
build/main.o
build/mathx.o
build/report.o
clean
```

Разберитесь, почему объектные файлы называются именно так (они лежат в `build/`), и приведите все цели, зависимости и команды к согласованному виду.

Требования:

* `all` не имеет команды, только зависимость от `calc`;
* `calc` зависит от трёх объектных файлов и линкует их: `gcc build/main.o build/mathx.o build/report.o -o calc`;
* каждый объектный файл собирается командой вида `gcc -Iinclude -c src/X.c -o build/X.o`;
* `clean` удаляет `build/*.o` и `calc`;
* `all` и `clean` не являются файлами, поэтому объявите их через `.PHONY`;
* перед первым `make` создайте папку `build` вручную: `mkdir build`.

Разберитесь в структуре правила `make` — она пригодится в следующих задачах:

```make
target: prerequisites
	recipe
```

### Инструменты

`make`, `gcc`, `mkdir`, `cat`, `man make`, `vim`

### Самопроверка

- `make` собирает `./calc`, а `./calc` выводит `add: 5` и `mul: 20` — сравните с `expected.txt`;
- `make clean && make` работает без ошибок;
- `make build/mathx.o` собирает только один объектный файл;
- вы можете объяснить, из каких трёх частей состоит любое правило (`target`, `prerequisites`, `recipe`).

## Задача 2. Расширяем Makefile: создание каталога, run и test

### Условие

Доработайте `hw1/Makefile`.

1. Добавьте создание папки `build` в сам Makefile. Сначала удалите папку, созданную вручную на прошлый шаг:

```bash
rm -rf hw1/build
```

Первой командой каждого правила, создающего объектный файл, поставьте `mkdir -p build`. Теперь `make` должен работать из чистой копии проекта, где `build/` нет.

2. Добавьте цель `run`: она собирает `calc` (если нужно) и запускает `./calc`.
3. Добавьте цель `test`: она запускает программу и сравнивает её вывод с `expected.txt`. Подсказка:

```make
test: calc
	./calc | diff - expected.txt
```

Если вывод совпал, `make` молчит. Проверьте, что `test` ловит ошибку: временно поменяйте `mul(4, 5)` на `mul(4, 6)` в `hw1/src/main.c`, запустите `make test`, затем верните файл как было.

4. Объявите все новые не-файловые цели в `.PHONY`.
5. Разберитесь, зачем перед командой ставится символ `@` и что делает `-` (минус) перед ним: `man make`, раздел про recipes.

### Инструменты

`make`, `diff`, `mkdir`, `rm`, `man make`, `vim`

### Самопроверка

- `rm -rf hw1/build && make -C hw1 run` печатает результаты без ручных шагов;
- `make -C hw1 test` молчит при верном коде и завершается с ошибкой при неверном;
- вы можете объяснить, что происходит в команде `./calc | diff - expected.txt`, почему `expected.txt` идёт после `-` и какими будут последствия, если перепутать порядок аргументов.

## Задача 3. Инкрементальная сборка

### Условие

Работайте во второй копии проекта, `hw2`. Скопируйте туда готовый Makefile из первой копии:

```bash
cp hw1/Makefile hw2/Makefile
```

1. Выполните `make -C hw2 clean && make -C hw2`, затем сразу `make -C hw2` ещё раз. Что напечатал второй запуск? Почему ничего не пересобралось? Ответ — в `make-results/answers.txt`.

2. Выполните по очереди три эксперимента. После каждого запускайте `make -C hw2`, записывайте, какие команды реально выполнились, и проверяйте времена файлов командой `stat -c '%n %y' hw2/build/*.o hw2/calc`:

* а) добавьте комментарий в `hw2/src/mathx.c`;
* б) верните файл в исходное состояние (повторное сохранение тоже меняет время файла — сравните поведение `make`);
* в) добавьте комментарий в `hw2/src/main.c`.

3. Сравните `touch hw2/src/mathx.c` и реальную правку файла: что изменилось в поведении `make`? Объясните, на что именно смотрит `make` — в `make-results/answers.txt`.

4. Теперь соберите чистый комплект файлов для артефакта: свежая сборка, затем правка только `main.c`. Выполните по порядку:

```bash
make -C hw2 clean
make -C hw2
stat -c '%n %y' hw2/build/*.o hw2/calc > make-results/timestamps-1.txt
```

Затем добавьте комментарий в `hw2/src/main.c`, снова запустите `make -C hw2` и сохраните новое состояние:

```bash
stat -c '%n %y' hw2/build/*.o hw2/calc > make-results/timestamps-edit.txt
```

5. Объясните в `answers.txt`, почему после правки `main.c` объектные файлы `mathx.o` и `report.o` остались со старым временем.

В конце верните `hw2/src/main.c` в исходное состояние и убедитесь, что `make -C hw2 test` снова проходит.

### Инструменты

`make`, `stat`, `touch`, `diff`, `man make`, `vim`

### Самопроверка

- после второго `make` не выполняется ни одной команды компиляции;
- после правки `mathx.c` пересобирается только `build/mathx.o` и перелинковывается `calc`;
- после правки `main.c` пересобирается только `build/main.o`;
- строки `build/mathx.o` и `build/report.o` в `make-results/timestamps-1.txt` и `make-results/timestamps-edit.txt` совпадают, а строка `build/main.o` — различается;
- `touch` «ломает» так же, как и правка: `make` сравнивает времена файлов, а не их содержимое.

## Проверка и сдача работы

### Артефакт

Работа сдаётся одним архивом. Его готовит проверяющий скрипт, но убедитесь, что каталог `make-results/` содержит все файлы:

| Файл | Как получить |
|---|---|
| `Makefile` | `cp hw2/Makefile make-results/Makefile` — финальная версия с целями `run` и `test` |
| `run.txt` | `(make -C hw2 run; echo "exit=$?") > make-results/run.txt 2>&1` |
| `test-ok.txt` | `(make -C hw2 test; echo "exit=$?") > make-results/test-ok.txt 2>&1` |
| `test-fail.txt` | вывод `make test` при намеренной ошибке (см. ниже) |
| `timestamps-1.txt` | задача 3, шаг 4 |
| `timestamps-edit.txt` | задача 3, шаг 4 |
| `answers.txt` | письменные ответы на вопросы из всех задач |
| `session.txt` | запись терминальной сессии (`script`) |

`test-fail.txt` получают так: поменяйте `mul(4, 5)` на `mul(4, 6)` в `hw2/src/main.c`, выполните

```bash
(make -C hw2 test; echo "exit=$?") > make-results/test-fail.txt 2>&1
```

затем верните `main.c` и убедитесь, что `make -C hw2 test` снова проходит.

### Как проверить работу

Из каталога задания выполните:

```bash
chmod +x check.sh
./check.sh
```

Скрипт проверит состав `make-results/`, финальный `Makefile`, выводы целей `run` и `test`, файлы времён и исходный проект, напечатает результаты проверок и, если всё в порядке, соберёт архив `s3-makefile.tar.gz`. Можно приложить скриншот этого вывода.

### Как передать работу

Отправьте файл `s3-makefile.tar.gz` своему семинаристу удобным способом — канал связи уточните на занятии (например, телеграм или почта). В теме сообщения укажите: `s3-makefile — ФИО`.
