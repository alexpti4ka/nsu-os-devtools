## Как начать работу

Сначала склонируйте репозиторий на свой компьютер:

```bash
git clone https://github.com/alexpti4ka/nsu-os-devtools.git
```

Перейдите в созданную папку:

```bash
cd nsu-os-devtools
```

В дальнейшем перед началом работы с материалами обновляйте локальную копию репозитория. Надёжный порядок действий:

```bash
# 1. Убедитесь, что вы внутри папки репозитория
cd nsu-os-devtools

# 2. Проверьте, что рабочее дерево чистое (нет незакоммиченных изменений)
git status

# 3. Заберите свежие изменения с сервера
git fetch origin

# 4. Влейте их в свою ветку main
git pull origin main
```

Команды `git pull` / `git fetch` необходимо выполнять **из папки `nsu-os-devtools`** (или той папки, куда вы клонировали репозиторий), а не из произвольного каталога.

### Почему `git pull` может не сработать и как это исправить

**1. «fatal: not a git repository (or any of the parent directories): .git»**
Команда выполнена не в папке репозитория. Перейдите в каталог клона: `cd nsu-os-devtools`. Проверить, что вы на месте, можно командой `git remote -v` — она должна показать адрес репозитория.

**2. «Your local changes to the following files would be overwritten by merge»**
В рабочем каталоге есть ваши правки, которые конфликтуют с обновлениями. Варианты:
- сохранить свои изменения: `git stash` → `git pull` → `git stash pop`;
- или отказаться от них (аккуратно! они будут потеряны): `git checkout -- .`

**3. «You have divergent branches and need to specify how to reconcile them»**
Возникает, если вы делали локальные коммиты, а удалённый `main` тоже ушёл вперёд, и git не знает, как их объединить. Варианты:
- просто скачать обновления, сохранив свои коммиты поверх: `git pull --rebase origin main`;
- или явно задать стратегию на будущее: `git config pull.rebase true`.

**4. «error: pathspec ...» / «HEAD detached» после pull**
Вы находитесь не на ветке `main` (например, смотрели старый коммит). Вернитесь на ветку:
```bash
git checkout main
git pull origin main
```

**5. Ошибка доступа / «Authentication failed» при fetch или pull**
Проверьте, что remote указан на публичный репозиторий: `git remote -v`. Если указан неверный адрес — исправьте:
```bash
git remote set-url origin https://github.com/alexpti4ka/nsu-os-devtools.git
```

**6. Коммит-«ребут» не помогает: локальный репозиторий в непонятном состоянии**
Если репозиторий сильно разъехался с сервером, проще всего пересинхронизироваться «с нуля»:
```bash
git fetch origin
git reset --hard origin/main
```
⚠️ Команда `git reset --hard` необратимо удаляет все локальные правки и коммиты, которых нет на сервере. Перед этим убедитесь, что вам нечего сохранять, либо сохраните нужное через `git stash`.
